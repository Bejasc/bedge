# Plan 009 — Starboard

**Depends on:** Plan 003 — guild config, the `/config` panel and the Components V2 style
**Feeds into:** Nothing downstream; the feature docs describe it
**Outcome:** When a message collects enough star reactions, bedge reposts it to the server's starboard channel and keeps the star count current.

A starboard turns the funniest and best messages in a server into a highlights channel without anyone curating it. It's one of the few Dyno-adjacent features members actually notice.

## Context

Ben asked for a starboard after the Dyno-replacement roadmap (Plans 003–008) was built. It reuses Plan 003's config panel and card style. Reactions need a gateway intent the bot doesn't have yet, and reaction events on old messages arrive partial, so they must be fetched before counting.

## Decisions Log

| Decision | Choice | Reason |
|---|---|---|
| Scope | One starboard per server | Covers the common case; multiple boards are config sprawl (assumed) |
| Config | `starboard { enabled, channelId, emoji, threshold, selfStar }` in `GuildConfig`, set from a new *Starboard* section of `/config`. Defaults: ⭐, threshold 3, self-stars don't count | Same panel as everything else (assumed) |
| Emoji input | A modal text field accepting a unicode emoji or a custom emoji (`<:name:id>` or `name:id`) | Discord has no emoji picker component (assumed) |
| Counting | Count the users who reacted with the board's emoji, excluding bots and, unless `selfStar` is on, the author | Stops self-promotion and bot inflation (assumed) |
| Below threshold | When the count drops below the threshold, the starboard post is deleted | The board reflects current consensus (assumed) |
| Ignored messages | Messages in the starboard channel, bot messages and messages in NSFW channels (unless the board itself is NSFW) | Avoids loops and leaking NSFW content (assumed) |
| Card | Components V2: author avatar and name, content, first image, `⭐ N · #channel`, *Jump to message* button | Matches the bedge look (assumed) |
| Storage | `StarboardEntry` model: source message, starboard message, count; unique per source message | Updates edit the existing post rather than reposting (assumed) |
| New intent | `GuildMessageReactions`, with `Reaction` and `User` partials | Required for reaction events (assumed) |

## Phase 1 — Config and storage

- [x] `starboard` block in the `GuildConfig` schema and model; `StarboardEntry` schema and model; schemas regenerated
- [x] *Starboard* section in `/config`: channel picker, toggle, threshold select, *Set emoji* modal, self-star toggle
- [x] Pure helpers with tests: emoji parsing and matching, star counting, post/update/remove decision

**Exit criteria:** A server can configure a starboard from the panel, and the counting rules hold under test.

## Phase 2 — Reactions and the board

- [x] `GuildMessageReactions` intent and partials
- [x] Listeners for reaction add, remove, remove-all and remove-emoji that recount and post, edit or delete the starboard card
- [x] Starboard card renderer with tests (component validity, image pick, truncation)

**Exit criteria:** Starring a message past the threshold posts it; more stars update the count; unstarring below the threshold removes it.

## Out of Scope

- Multiple starboards or per-channel thresholds
- A "star of the week" digest
- Starboard leaderboards

- [ ] Removing stars below the threshold removes the post; self-stars and bot reactions don't count (live check)
- [x] Changes committed to git
